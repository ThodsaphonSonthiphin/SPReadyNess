When the app can't vouch for a number

Colour carries the recommendation, so a score the app cannot stand behind is shown without it — stale (ADR 0009) or RHR-absent so the override never ran (ADR 0005). The empty state is different again: nothing has ever been captured, so there is no number to dim (ADR 0015).

What changed in rev 3 — after scrutiny

  • The uncoloured state is now drawn (01·s, 02·s). A review found ADR 0009 mandated a second visual state on every score-bearing surface that no mockup had ever shown — the state most likely to ship wrong was the one nobody had looked at.
  • The dashed Now arc is now in the baseline. Rev 2 invented it here without documenting it in design-baseline.md — exactly the mockup-vs-build drift the baseline exists to prevent.
  • Now Score reads two inputs, not three. restingHeartRate is a daily profile value and cannot change intraday, so screens 02 and 03 necessarily share an RHR of 89. The evening drop is Body Battery and Recovery alone.
  • Capture mechanism defined — a guarded 30-minute Duration event (ADR 0012), with Body Battery resolved back to wakeTime rather than read at firing (ADR 0013), so the 50%-weighted input is not biased by how late the event happened to run.
  • Still unverified — background memory ceiling and the Application.Storage limit. The averageRestingHeartRate window and restingHeartRate freshness remain assumptions, now recorded as such in ADR 0004 rather than left loose.
